카드 규칙:
- 정확히 {{count}}장. id는 C1부터.
- 카드 하나 = 상황(scenario) 하나 + 질문 칸(slots) 2~3개. 칸들은 같은 상황의 서로 다른 결과를 묻는다.
- 상황은 경계값, 이상 입력, 외부 호출 실패·지연·이상 응답, 순서·재시도, 동시 요청, 상태가 남거나 지워지는 지점처럼 **예측이 틀리기 쉬운 곳**을 고른다. 위 우선 출제 대상과 관련된 카드를 먼저 만든다. 절반 이상은 정답이 직관과 다른 카드로 한다.
- 묻는 결과는 **Python 서버 코드를 실행해서 관찰할 수 있는 것**만: HTTP 상태 코드, 응답 본문의 특정 필드 값·개수, 저장된 상태(파일·메모리·DB)의 변화, 외부 클라이언트 호출 횟수, 발생한 예외 종류, 로그 기록 여부. 브라우저·JS 화면 동작은 묻지 않는다.
- **읽는 사람**: 응시자는 이 시스템을 며칠 전에 AI와 함께 만들었고 세부는 잊었다. 코드를 보지 않고 카드만 읽어도 무엇을 묻는지 바로 알 수 있어야 한다.
- context: 이 카드가 다루는 기능 흐름을 **사용자 행동에서 결과까지** 1~2문장, 200자 이내로 쓴다 (예: "직원이 통화 연습 녹음을 마치면 서버가 음성을 글로 옮기고, 외부 분석 모델에게서 고칠 점을 받아 돌려준다. 고칠 점마다 직원 발화에서 그대로 따온 인용이 붙는다."). 카드에 나오는 도메인 용어는 여기서 풀어 쓴다. 단 정답을 정하는 처리(검증, 재시도, 거절 조건, 걸러내기)는 쓰지 않는다.
- scenario: 누가 무엇을 하는지(어떤 사용자 행동·요청인지) + 이번에 벌어지는 이상 조건. 2문장, 160자 이내. 주입 조건은 구체적으로 (예: "외부 분석 모델이 빈 JSON 객체 {} 를 돌려준다", "음성 파일이 10MB보다 1바이트 크다").
- 금지 표현 (context, scenario, 칸 질문, 선택지 모두):
  - 프로젝트 안에서만 통하는 코드·번호: 기준 번호(B1, B3), 테스트 번호(T8), 결정 번호(D16a), 합의 번호(#12-1), 그 밖에 임의로 붙인 ID. 뜻으로 풀어 쓴다 (예: "B1 고칠 점" → "먼저 공감하지 않았다는 지적").
  - 함수명·변수명·파일 경로·JSON 필드명. 역할과 뜻으로 가리킨다 (예: "재연습 분석 요청", "고칠 점 목록", "인용").
  - 측정·주입 방법과 내부 기술 용어: "가짜로 바꾼다", "호출 수를 센다", "기록한다", 이벤트 루프, 밀리초 타이머, 동기/비동기, monkeypatch. 동시성 카드는 "두 직원이 거의 동시에 분석을 요청한다"처럼 사용자 쪽 사건으로 쓰고, 결과는 시간 값 대신 순서·횟수로 묻는다.
- 칸 질문은 그것만 읽어도 완결된 문장으로 쓴다 (주어·단위 포함, 예: "이 분석 요청 한 번을 처리하는 동안 외부 분석 모델은 몇 번 호출되나?"). 칸 순서는 일이 일어나는 순서를 따른다.
- 선택지는 뜻이 바로 보이게 쓴다 (예: "고칠 점 없음", "공감 지적 1개, 인용은 비어 있음").
- 칸 종류:
  - choice: 선택지 2~4개, 서로 겹치지 않게. 예/아니오 질문은 options ["예", "아니오"].
  - value: 숫자·상태 코드·개수·짧은 토큰처럼 정확히 일치로 채점할 수 있는 값만. 문장은 금지.
- claimed: 네가 예상하는 정답. choice는 options 중 하나와 글자까지 같게, value는 값 그대로.
- explanation: 실제로 그렇게 되는 코드 경로를 순서대로 2~4문장. 근거 줄은 evidence에 "파일:줄" 또는 "파일:시작-끝"으로 단다 (파일 경로는 파일 트리에 있는 그대로).
- defect_tags: 해당하는 결함 패턴 ID (없으면 빈 배열).

probe 규칙 (가장 중요):
- 한 카드당 pytest 파일 하나, 테스트 함수 하나. 파일은 저장소 루트 아래 `{{probe_dir}}/`에 놓이고, 저장소 루트를 현재 디렉터리로 `python -m pytest`로 실행된다. 저장소 모듈은 루트 기준 경로로 import 한다.
- `observe(key, value)` 함수는 이미 정의되어 있다. 정의하거나 import 하지 않는다.
- 저장소 코드를 실제로 import 해서 실행한다 (FastAPI면 `fastapi.testclient.TestClient`). 코드를 다시 구현하거나 결과를 상수로 만들어 내면 안 된다.
- 외부 API·모델 호출은 `monkeypatch` 로 상황에 맞는 가짜로 바꾼다. 실제 네트워크 호출은 실패한다. 가짜가 몇 번 불렸는지 셀 수 있게 만든다.
- 파일·디렉터리를 쓰는 코드라면 `tmp_path`나 monkeypatch로 경로를 돌린다.
- 각 칸 id마다 `observe("<칸 id>", 값)`을 정확히 한 번 호출한다. choice 칸은 실제 관찰값에서 계산한 options 문자열을 observe 한다 (예: `observe("s2", "비워짐" if body["previous_issues"] == [] else "유지")`). 그 계산은 모든 선택지를 구분할 수 있어야 하고, 어느 선택지에도 맞지 않으면 "기타:<관찰값>"을 observe 한다.
- 정답을 assert 하지 않는다. 결과가 예상과 달라도 테스트는 통과해야 한다. 상황 준비가 실제로 됐는지 확인하는 assert(예: 가짜가 한 번이라도 불렸는지)만 허용한다.
- 예외가 나는 상황이면 try/except로 잡아서 예외 이름을 observe 한다.

모든 문장형 텍스트 값은 한국어로 쓴다. 코드 식별자·파일명·경로·인용문은 원문 그대로 둔다.
JSON 스키마로만 출력한다.
